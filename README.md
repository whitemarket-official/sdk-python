# WhiteMarket Python SDK

[![CI](https://github.com/whitemarket-official/sdk-python/actions/workflows/ci.yml/badge.svg)](https://github.com/whitemarket-official/sdk-python/actions/workflows/ci.yml)
[![PyPI](https://img.shields.io/pypi/v/whitemarket-sdk.svg)](https://pypi.org/project/whitemarket-sdk/)
[![License: MIT](https://img.shields.io/badge/license-MIT-blue.svg)](LICENSE)

> Status: `0.1.0` is not released yet. The public API may change until `1.0.0`; while the version is `0.x`, a minor
> release may contain breaking changes, always listed under "Breaking" in the [changelog](CHANGELOG.md).

Official Python SDK for the [WhiteMarket](https://white.market) partner API (CS2 skins marketplace).

- **Generated layer**: a typed client for every operation of the partner GraphQL schema
  (`https://api.white.market/graphql/partner`), regenerated by a GitHub Actions workflow when the schema changes.
- **High-level client**: Partner Token authentication with a cached, automatically renewed access token, market search,
  buying with an idempotent `custom_id` and outcome reconciliation, deal tracking, selling, inventory, wallet, profile
  and store. Everything exists as a sync client (`WhiteMarketClient`) and an async client (`AsyncWhiteMarketClient`)
  with the same method names.
- **Export files**: streaming access to the public price and product exports on `https://export.white.market`, with
  freshness metadata.
- **Live updates**: Server-Sent Events and WebSocket (Centrifugo) with typed events and automatic reconnect.

Not shipped yet: the high-level `orders` (buy orders) module. The generated `order_*` operations work through
`client.generated`; the module is planned for the next minor release.

## Install

```bash
pip install whitemarket-sdk                    # GraphQL client only
pip install "whitemarket-sdk[exports]"         # + streaming export files (ijson)
pip install "whitemarket-sdk[live]"            # + WebSocket live updates (websockets)
pip install "whitemarket-sdk[exports,live]"
```

The base install depends on `httpx` and `pydantic`. Reading an export file without the `exports` extra raises an `ImportError`
naming the extra (JSON streaming needs `ijson`); without the `live` extra only SSE live updates work
(`LiveTransport.SSE`), and the default WebSocket transport raises an `ImportError` naming the extra.

Contributors: `make install` sets up the development setup with uv or pip, see [CONTRIBUTING.md](CONTRIBUTING.md).

## Requirements

Python 3.11 or newer: every CPython version in bugfix or security status (3.11 to 3.15 at the time of writing,
<https://devguide.python.org/versions/>). The package is fully typed (`py.typed`; `mypy --strict` and pyright strict
clean).

## Quickstart

Create a Partner Token in your WhiteMarket account and export it. The SDK reads it and never prints it.

```bash
export WHITEMARKET_PARTNER_TOKEN=...
```

```python
from whitemarket import WhiteMarketClient
from whitemarket.market import ProductFilter
from whitemarket.models import App, Money, PageRequest

with WhiteMarketClient.from_env() as client:
    print(client.auth.ping())  # connectivity and credentials check
    page = client.market.search(
        ProductFilter(app=App.CSGO, price_to=Money.usd("5.00")), PageRequest(first=10)
    )
    for product in page:
        print(product.id, product.price)  # Money prints as "1.50 USD"

    # Buy the cheapest listing of an item, at most 5 USD. THIS SPENDS MONEY.
    result = client.buying.buy_cheapest(
        App.CSGO, "AK-47 | Redline (Field-Tested)", max_price=Money.usd("5.00")
    )
    print(result.deal.id, result.custom_id)
```

The async client has the same methods; every call is awaited and iterators are `async for`:

```python
import asyncio

from whitemarket import AsyncWhiteMarketClient
from whitemarket.market import ProductFilter
from whitemarket.models import App, Money


async def main() -> None:
    async with AsyncWhiteMarketClient.from_env() as client:
        async for product in client.market.iterate(ProductFilter(app=App.CSGO, price_to=Money.usd("5.00"))):
            print(product.id, product.price)
            break  # iterators are lazy: no further page is requested


asyncio.run(main())
```

Money and wear values are `decimal.Decimal` (`Money.amount`), never `float`: `Money.usd(1.5)` raises `TypeError`, pass
`"1.50"` or a `Decimal`. 64-bit ids (asset, class, instance) are strings. Datetimes are timezone-aware.

## Authentication

```python
WhiteMarketClient(partner_token="...")        # preferred: the SDK exchanges it for access tokens and renews them
WhiteMarketClient(access_token="eyJ...")      # you manage the access token (JWT) yourself
WhiteMarketClient(token_provider=my_provider) # full control: a TokenProvider with access_token() / refresh()
WhiteMarketClient.from_env()                  # WHITEMARKET_PARTNER_TOKEN (and optional WHITEMARKET_BASE_URL)
```

Pass exactly one credential. A Partner Token is exchanged with `auth_token`; the access token is cached, renewed 5
minutes before it expires, refreshed once on a 401 (the request is then replayed once, within the same attempt budget:
a query sends at most `max_attempts` requests), and concurrent callers share one exchange (single flight). A token whose
`exp` is already past or less than 5 minutes ahead serves the request that asked for it and is exchanged again before
the next one. Tokens and Partner Tokens are `whitemarket.Secret` values: `repr` and `str` print `***`;
`secret.reveal()` returns the text.

**Several processes or workers**: share one `TokenStore` (`get()`, `set(token, expires_at)`, `clear()`; the async client
takes an `AsyncTokenStore`) so that N workers do not each call the rate-limited `auth_token`. The default is
`InMemoryTokenStore` / `AsyncInMemoryTokenStore`. Use one store (one key of a shared cache) per Partner Token.

```python
from whitemarket import InMemoryTokenStore, WhiteMarketClient

store = InMemoryTokenStore()  # replace with your own TokenStore backed by Redis, a file, ...
client = WhiteMarketClient(partner_token="...", token_store=store)
```

## Buying

```python
from whitemarket.models import App, Money

result = client.buying.buy_cheapest(App.CSGO, "AK-47 | Redline (Field-Tested)", max_price=Money.usd("5.00"), custom_id=my_id)
result = client.buying.buy_product(product.id, Money.usd("5.00"), custom_id=my_id)
result = client.buying.buy_by_asset_id(App.CSGO, "123456789", Money.usd("5.00"), custom_id=my_id)
```

`BuyResult` has `deal`, `custom_id` and `reconciled`.

**Idempotency and reconciliation.** A purchase is a GraphQL mutation and mutations are **never retried**, by the transport
or by anything else. Every purchase carries a `custom_id` (1 to 100 characters; a UUIDv4 when you pass none). If the
answer is lost (timeout, 5xx, a response that cannot be read), the SDK does not know whether the purchase happened: it
waits (`BuyReconciliation.delay`, 10 to 20 s, default 15 s), then looks the deal up by `custom_id`
(`attempts` times, `interval` apart, defaults 3 and 5 s).

- The deal is found: you get a normal `BuyResult` with `reconciled=True`.
- A GraphQL rejection before the purchase ran (insufficient funds, the listing is gone, ...): a `GraphQLError`; nothing
  was bought.
- No deal is found: `PurchaseOutcomeUnknownError` (`custom_id`, `last_lookup_error`, the original failure as
  `__cause__`). **Do not buy again with a new id.** Look the deal up later with `client.deals.get(custom_id)`; only a
  retry with the *same* `custom_id` is safe.

**Persist the `custom_id` in your own storage before you call the buy method**, so it survives a crash between the
request and the answer. `examples/buy_cheapest_by_name.py` and `examples/buy_product_by_id.py` show the whole flow.

## Deal tracking

```python
from whitemarket.deals import Until

state = client.deals.wait_for(deal_id_or_custom_id, Until.exchanged_or_completed(), poll_interval=30.0)
print(state.status.value)  # DealState: id, custom_id, status, cancel_reason, price, ...
```

`wait_for` polls `deal_buyer_statuses` (one request for the deal; `deals.statuses(ids)` takes up to 300 ids), works for
seller deals too, and has no timeout unless you pass `timeout=` (a trade can take hours, so waiting without a limit is the
sensible default; `DealWaitTimeoutError` carries the last state). Every `Until` predicate (`offered`,
`exchanged_or_completed`, `completed`, `final`) also matches a final status, so a wait never outlives a cancelled or
reversed deal: check `state.status`. `DealStatus` has `is_in_progress()`, `is_exchanged()`, `is_successful()`,
`is_failed()`, `is_reversed()`, `is_final()`. Other deal methods: `get`, `statuses`, `list_as_buyer`, `list_as_seller`,
`history`, `iterate_history`, `request_cancel`, `report_offer_sent`, `cancel_sending_offer`, `hold_balance(s)`.

**Live wake-up.** Pass a live session whose personal channel is subscribed and `wait_for` polls early when an event of the
deal arrives (an event is a hint; the state is always read from the API):

```python
with client.live() as live:
    live.subscribe_personal()
    state = client.deals.wait_for(deal_id, Until.exchanged_or_completed(), poll_interval=30.0, live=live)
```

Examples: `track_deal_polling.py`, `track_deal_live.py`.

## Selling

```python
from whitemarket.models import DeliveryType, Money

product = client.selling.list(item, Money.usd("12.50"), delivery_type=DeliveryType.SEMI)
client.selling.reprice(product.id, Money.usd("11.90"))
client.selling.remove(product.id)
```

- **SEMI**: WhiteMarket sends the Steam trade offer; you confirm it in Steam Mobile. Follow the deal until `EXCHANGED`
  (`examples/sell_semi.py`).
- **MANUAL**: you send the Steam trade offer yourself, to the buyer's `Deal.receiver_trade_url` (a `Secret`), then call
  `client.deals.report_offer_sent(deal_id, steam_offer_id)`. If you cannot send the item, `deals.cancel_sending_offer()`
  with the TRUE reason: a wrong one can lead to sanctions (`examples/sell_manual.py`).

`list_many`, `reprice_many` and `remove_many` take many items, send one request per chunk (`selling_batch_size`, default
100; the server's maximum is unconfirmed) and return one `BatchItemResult` per item, in your order, with the outcome
`SUCCEEDED | FAILED | UNKNOWN | NOT_SENT`. Unless every item has a server-reported outcome they raise
`BatchIncompleteError` (`results` holds what is known). Selling mutations have no idempotency key and are sent once: after
an ambiguous failure check `client.selling.my_products()` before repeating.

## Inventory, wallet, profile, store

```python
page = client.inventory.list()                       # also iterate(); refresh_from_steam() re-reads your Steam inventory
balances = client.wallet.balances()                  # balance(currency), deposits, withdrawals, transactions, transfers, credit
profile = client.profile.get()                       # set_trade_url, set_steam_proxy, set_steam_token, set_email, ...
store = client.store.get()                           # edit(StoreSettings(...))
```

`wallet.take_credit` and `wallet.transfer` move money and are sent once, never retried; when the outcome is unknown they raise
`MutationOutcomeUnknownError` whose message says where to check (`wallet.credit()` / `wallet.transfers()`). Steam proxy and
token payloads are `Secret` parameters. Filters are the dataclasses `InventoryFilter`, `WalletTransactionFilter`,
`StoreSettings` and the like; every list method has a one-page form (`list`) and a lazy iterator (`iterate*`).

Orders (buy orders): not available in the high-level client yet; see the generated layer below.

## Exports

The export files are public: no token. `ExportClient` (and `AsyncExportClient`) is also available as `client.exports`.
Needs the `exports` extra.

```python
from whitemarket import ExportClient
from whitemarket.exports import ExportWindow

with ExportClient() as exports:
    prices = exports.prices(window=ExportWindow.MINUTES10, max_age=900)  # refuse data older than 15 minutes
    row = prices.get("AK-47 | Redline (Field-Tested)", "282")           # (market_hash_name, paint_index)
    print(row.price if row else "not listed")

    with exports.stream_products(window=ExportWindow.MINUTES10) as rows:  # millions of rows, constant memory
        for row in rows:
            ...  # leaving the loop closes the connection
```

`prices()` returns a `PriceList` (`get(name, paint_index="0")`, `all_phases(name)`; with `conditional=True` it may return
`NotModified`). `stream_prices`, `stream_products` (JSON or CSV) yield rows lazily; `meta()` reads the freshness sidecar
(`data_as_of`, `generated_at`, `items`); `max_age` raises `StaleExportError` before the file is downloaded; `download()`
writes a file atomically. Rows keep unknown server fields in `extra`. Only export requests follow redirects (same
origin rules apply). Examples: `export_prices_lookup.py`, `export_products_stream.py`.

## Live updates

```python
from whitemarket import LiveTransport, WhiteMarketClient

with WhiteMarketClient.from_env() as client, client.live(LiveTransport.SSE) as live:
    live.subscribe_products()
    event = live.poll(5.0)           # blocking, returns None after the timeout
```

`client.live(transport, options)` returns a `LiveSession` (sync: a background thread, blocking `poll(timeout)`, `run`,
handlers on the caller's thread) or an `AsyncLiveSession` (async client: `await poll()`, `async for event in live`).
`LiveTransport.WS` (default, needs the `live` extra) or `LiveTransport.SSE` (unidirectional); `LiveOptions` bounds the
connect time, the SSE event size and the number of reconnects. Events are frozen dataclasses: `ProductAdded`,
`ProductEdited`, `ProductRemoved` (public channel, `subscribe_products`), the personal deal events `DealInitiated`,
`DealOffered`, `DealNeedConfirmation`, `DealExchanged`, `DealCompleted`, `DealExpired`, `DealCancelled`, `DealHold`
(`subscribe_personal`), and `UnknownEvent` for a type the SDK does not know. Register with `live.on(EventType, handler)`
and `on_connected`, `on_disconnected`, `on_error`, `on_connecting`. The SDK reconnects with backoff and fetches a fresh
access token before every connect. Events missed while reconnecting are not replayed: when `on_connected` reports
`reconnected=True`, re-read what you need. Product prices are assumed to be USD. Examples: `sse_products_feed.py`,
`ws_products_feed.py`, `ws_personal_deals.py` (async).

## Generated layer

`client.generated` exposes every operation of the schema as a typed method, on the client's own token, retry policy and
error mapping. Its names follow the schema (`market_list`, `forward_pagination`), and the typed inputs live in
`whitemarket._generated`. `execute(document, variables)` sends a hand-written document:

```python
from whitemarket._generated.input_types import ForwardPaginationInput

listing = client.generated.market_list(forward_pagination=ForwardPaginationInput(first=3))
data = client.generated.execute("query Ping { test_ping }")   # the raw `data` dict
```

A document that is not clearly a query is treated as a mutation and is never retried. Use the generated layer for what the
high-level client does not cover yet (for example `order_*`). Example: `raw_generated_operation.py`.

## Errors

```
WhiteMarketError
├── TransportError                      network failure before a response
├── DecodeError                         a response that does not have the expected shape
├── HttpError (status, body_excerpt)
│   ├── BadRequestError (400)
│   ├── AuthenticationError (401, after the one refresh and replay)
│   ├── RateLimitError (429, retry_after)
│   └── ServerError (5xx)
│       └── ServiceUnavailableError (503, retry_after)
├── GraphQLError (errors, partial_data)
│   └── NotFoundError                   every error's category ends with ".not_found"
├── PurchaseOutcomeUnknownError         see Buying
├── MutationOutcomeUnknownError         see Inventory, wallet, profile, store
├── BatchIncompleteError                see Selling
├── DealWaitTimeoutError
├── ExportError
│   ├── GeneralExportError
│   └── StaleExportError
└── LiveConnectionError (code, reason)
```

**Branch on `extensions.category`, never on an error message**: `GraphQLErrorEntry.category` (and `GraphQLError.has_category`)
carry it; `whitemarket.errors.ErrorCategory` names the categories the SDK knows. The server does not publish its category
catalogue, so an unknown category arrives as a plain string. The message is server text: not redacted, never parse it.
`HttpError.body_excerpt` is at most 512 bytes with credentials replaced by `***`. Unknown is not an error: a new enum value
decodes to an unknown pseudo-member (`is_unknown`), a new event type to `UnknownEvent`.

## Retries and timeouts

- GraphQL **queries** are retried (3 attempts in total by default) on a network error before a response and on 429, 500,
  502, 503 and 504, with exponential backoff and full jitter (`RetryPolicy`: base 0.5 s, factor 2, cap 30 s). A 429 or
  503 with `Retry-After` is not retried: you get `RateLimitError` / `ServiceUnavailableError` with `retry_after` at once.
- **Mutations are never retried** (there is no switch). A 401 refreshes the token once and replays once, because it means
  the request was rejected before it ran. The replay counts against the same attempt budget: a query sends at most
  `max_attempts` requests (a 401 on the last attempt is still replayed once), a mutation at most two.
- Export GETs are retried on 429 and 5xx; live connections reconnect with backoff.
- `Timeouts(connect=10, request=30)` seconds. `RetryPolicy.none()` disables query retries.

## Configuration reference

`WhiteMarketClient(...)` / `AsyncWhiteMarketClient(...)` keyword-only options; `from_env()` accepts every option except the
credentials.

| Option | Meaning |
|---|---|
| `partner_token`, `access_token`, `token_provider` | exactly one credential |
| `token_store` | where the cached access token lives (with `partner_token` only) |
| `base_url`, `graphql_path`, `export_base_url`, `sse_url`, `ws_url` | endpoint overrides (https, no embedded credentials, printable ASCII up to 2048 characters, an internationalised host in its `xn--` form; `sse_url` without a query: the SDK appends its own) |
| `http_client` | an `httpx.Client` (`httpx.AsyncClient` for the async client), see below |
| `timeouts`, `retry` | `Timeouts`, `RetryPolicy` |
| `logger` | a `logging.Logger` (default: `logging.getLogger("whitemarket")`) |
| `user_agent_suffix` | appended to the `User-Agent` |
| `buy_reconciliation` | `BuyReconciliation(delay=15, attempts=3, interval=5)` |
| `max_response_bytes` | cap on a response body (default 32 MiB) |
| `selling_batch_size` | items per request of the `*_many` selling methods (default 100) |

**Injected HTTP clients.** An injected `http_client` serves queries and mutations; the SDK cannot set its timeouts, does not
close it and trusts it not to resend a request whose connection failed. Every SDK request is sent with
`follow_redirects=False` and `auth=None` per request, so the client's own redirect policy and `auth` never apply (a
followed redirect would resend a credential header, and a mutation, to another host). A 3xx answer is an `HttpError` and
is not retried. TLS verification is always on; there is no switch to turn it off.

## Logging and redaction

The SDK logs through the standard `logging` module (logger `whitemarket`, or the one you pass). Request lines, retries and
reconnects are logged; credentials never are: the `Authorization` and `X-partner-token` headers, `cf_connect` URL
values, the bodies of `auth_*` and `profile_token_set`, and Steam ids are redacted. The WebSocket libraries log every frame
at DEBUG; the SDK drops those records of the `centrifuge` and `websockets.client` loggers. Credentials are `Secret` values
everywhere they are stored or passed. Server error messages and `partial_data` are raw server data.

## Versioning and schema updates

The SDK follows [Semantic Versioning](https://semver.org/); while `0.x` a minor release may break the API, and every
breaking change is listed under "Breaking" in the [changelog](CHANGELOG.md) with `before -> after`.

The generated layer follows the partner schema. A GitHub Actions workflow (`schema-sync.yml`) introspects the schema every
day; when it changed, it regenerates the operations and the client, runs `make check` and opens a pull request on the branch
`schema-sync/auto` labelled `schema-update` (plus `breaking` when the diff holds breaking changes). The PR carries the
change summary (`schema/CHANGES.md`); a maintainer decides whether the high-level layer needs changes and which SemVer bump
applies. Nothing is pushed to `main` directly.

## Examples

Runnable scripts in [`examples/`](examples/); run one with `make example NAME=search_market` or
`python examples/search_market.py`. Everything except the export examples needs `WHITEMARKET_PARTNER_TOKEN`. The scripts that
move money (`buy_*`, `sell_*`) print a dry run and do nothing without `--yes`. A failure is printed with its class, HTTP status
and each GraphQL error's category, path and message.

| Example | What it does |
|---|---|
| `auth_and_ping` | exchange the token, `test_ping` |
| `search_market` | first page of cheap CS2 listings |
| `iterate_all_listings` | lazy, bounded walk over listings |
| `buy_cheapest_by_name` | buy the cheapest listing of an item (reconciliation), `--yes` |
| `buy_product_by_id` | read a listing, refuse above a max price, buy it by id with a `custom_id`, `--yes` |
| `track_deal_polling` | wait for a deal by polling every 30 s, prints every status change |
| `track_deal_live` | the same, woken early by live events |
| `sell_semi`, `sell_manual` | the two selling flows, `--yes` (assume a seller deal's product id equals the listed product id; not confirmed by the docs) |
| `export_prices_lookup`, `export_products_stream` | export files, no token |
| `sse_products_feed`, `ws_products_feed` | five live product events |
| `ws_personal_deals` | personal deal events (async client) |
| `raw_generated_operation` | the generated layer and `execute` |
