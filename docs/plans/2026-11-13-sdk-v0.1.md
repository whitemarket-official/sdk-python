## Architecture decisions taken up front (ADRs written in the phase that needs them)

| Topic | Decision | ADR |
|---|---|---|
| Sync + async | Hand-written code lives once, in async form (`src/whitemarket/_async/`); the sync variant (`src/whitemarket/_sync/`) is produced by `tools/unasync.py` (token rewriting, the approach of httpcore) and committed; `make codegen-check` fails when it is stale. No event loop inside the sync client. | 0002 |
| Generated layer | ariadne-codegen (spike first), custom base client so our transport owns auth/retry/errors | 0001 |
| High-level models | frozen, slotted, keyword-only dataclasses; pydantic only in the generated layer | 0003 |
| Money / wear | `decimal.Decimal`; 64-bit ids as `str` | 0003 |
| Enums | `enum.StrEnum` with an `UNKNOWN` member; the raw server value is kept next to it | 0003 |
| Exports | `ijson` (`use_float=False`), optional extra `[exports]` | 0005 |
| Live WS | `centrifuge-python`, async; sync client exposes live through its own decision in the ADR | 0006 |

1. (P0) `uv` is not installed on the host: `make install` uses `python3 -m venv .venv` + pip. Install `uv`? Default: venv + pip.

4. (P0) Agent tooling is ported from the PHP SDK's `.claude/` (already the English, SDK-adapted port of the backend's)
   instead of re-translating the backend's Russian originals; backend files are read only to check nothing generic was lost. Default: as described.

5. (P1) The committed `schema/partner.graphql` was NOT the 2026-11-10 snapshot: it was the unsorted 2026-10-30 file
   (2412 vs 2635 lines; no `Achievement*` types etc.). A fresh introspection (2026-11-13, `fetch-schema.mjs`) is
   byte-identical to PHP's `schema/partner.graphql` and `partner.introspection.json`, so the fresh one is committed;
   `schema/CHANGES.md` copied from PHP. Default: fresh schema = PHP snapshot.

6. (P1) Unknown enum values: generated and high-level enums use a pseudo-member `UNKNOWN` of the same enum that
   keeps the raw value (ADR 0001), PHP uses a separate `UnknownEnumValue` type. Default: pseudo-member (idiomatic).
7. (P1) ariadne-codegen 0.19.0 pins `ruff<0.16`, so it runs in its own venv `.venv-codegen` (`make install-codegen`).
   Default: separate venv. If an ariadne upgrade breaks the plugin, fall back to an own graphql-core generator.
8. (P1) Deprecated operation arguments (`market_buy(deliveryType)`) are not marked deprecated in generated signatures
   (the spec asks it for input fields only). Default: documented only in the high-level layer, which hides them.

9. (P0, manual) Three hook test scripts are committed without the executable bit (`hooks-test-agent-guard.sh`,
   `suppress-check-test.sh`, `reuse-check-test.sh`): `block-dangerous-bash.sh` blocks `chmod` on `.claude/hooks/`
   by design. They run through `bash` in `make hooks-test`. Owner: `chmod +x` by hand if wanted.
10. (P0) The ported `.claude/` (security zone) needs a human review (CODEOWNERS) before merge.

11. (P2, public API) The sync client cannot bound the total request time with httpx: the deadline is checked between
    reads, so an attempt ends within `request` + one read timeout; async is a hard bound (DEVIATIONS row). Default: as is.
12. (P2, public API) `TokenProvider`, `TokenStore`, `InMemoryTokenStore` exist as sync and `Async*` twins (a sync client
    cannot await a store). Default: twins.
13. (P2, retry rule) Raw `execute()` infers the operation type like PHP and also takes `operation_type`; a declared
    `"query"` must not override a document that contains a mutation (fix in the review round). Default: inference wins
    for mutations.
14. (P2) An injected httpx client is used as is (it may follow redirects; README warns). Alternative: force
    `follow_redirects=False` per request also for injected clients. Default: as is (spec text).
15. (P2) Body excerpt redaction keeps float literals as sent (`1e2`), PHP re-encodes (`100.0`) (DEVIATIONS row).
16. (P2) Mutations use a separate httpx client without keep-alive (`Connection: close`) although httpcore never resends
    written HTTP/1.1 bytes [code, ADR 0002]: httpcore does not document it. Default: no reuse (spec 1.4).

17. (P2, auth) JWT expiry follows PHP / ADR 0003: an `iat`-based lifetime counted from the local clock, capped at 24 h,
    a past or non-positive `exp` cached up to 24 h (the server's 401 then triggers one refresh + replay). Proposal: a
    past or within-margin `exp` counts as expired; change PHP and ADR first. Default: PHP behaviour.
18. (P2, retry) The 401 replay gets a fresh attempt budget like PHP, so a query can send up to 2 x `max_attempts`
    requests. Proposal: one budget per call (SDK_SPEC 1.4 + PHP first). Default: PHP behaviour.
19. (P2) Suppression comments need an issue reference; no GitHub issue exists, `#0` is the placeholder in
    `pyproject.toml` per-file ignores. Owner: open an issue and replace it.
20. (P5, security) ijson 3.6.0 C backend (`yajl2_c`) segfaults on an integer token longer than
    `sys.get_int_max_str_digits()` (4300) [observed, CPython 3.13.3]. The SDK refuses such digit runs before ijson
    (DecodeError). Report upstream (ijson issue)? Default: guard + DEVIATIONS row, no upstream report from this session.
21. (P5) `Currency`, `DeliveryType`, `DeliveryPromise` are re-exported from the generated enums (one copy); a schema
    sync changes them. Default: re-export.

22. (P5/P2, security; replaces the default of question 14) Every SDK request (GraphQL, auth, export, SSE) passes
    `follow_redirects=False` and `auth=None` per request, so an injected httpx client cannot follow a redirect or add
    a credential either (stricter than "used as is"; found by the export verifier). Default: forced per request.
23. (P6) `centrifuge-python` keeps an unbounded internal queue and connects with `max_size=None`; the SDK disconnects a
    slow consumer instead of buffering (DEVIATIONS). Alternative: own Centrifugo protocol over an explicitly declared
    `websockets` dependency, as PHP did over its WS library. Default: keep centrifuge-python.

24. (P3, money) A malformed GraphQL error entry (bad `path`, non-object entry, missing `message`) of `market_buy`
    counts as "may have run" and is reconciled (PHP reaches the same outcome through a decode exception). Default: reconcile.
25. (P3, money) `data: {}` is kept as an empty object (reconciled), not turned into null (clean rejection). Default: PHP parity.
26. (P3, money) Only `Exception` triggers reconciliation; `CancelledError` / `KeyboardInterrupt` during `market_buy`
    propagate at once, so the outcome is unknown to the caller (README: persist `custom_id` before buying). PHP catches
    every `Throwable`. Default: propagate.

27. (P3, idempotency) A batch selling chunk answered 401 after the transport's refresh + replay is `NOT_SENT`
    (the server rejected it before execution, SDK_SPEC 1.4); PHP treats a client-thrown auth exception as ambiguous
    (in Python a client exception is always a `TransportError`, so it stays `UNKNOWN`). Default: `NOT_SENT`.
28. (P3) `selling.list` takes keyword arguments (Python named arguments, SDK_SPEC 3.3 rule 5 idiom); `list_many` takes
    a `ListingOptions`. Default: as is.

29. (P3, money; stricter than PHP) Buy reconciliation refuses a found deal whose `customId` differs from the one
    looked up (or is null): it counts as a failed lookup. Proposal for PHP + SDK_SPEC 3.3. Default: strict.
30. (P3; differs from PHP) `deals.wait_for(live=...)` holds an early wake-up until at least 1 s after the poll began
    (a burst of deal events no longer causes back-to-back polls); the deadline uses `time.monotonic`. Default: as is.
